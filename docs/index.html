worklog-studio

จากนั้นเปิด http://127.0.0.1:8765 ในเบราว์เซอร์ ถ้ายังไม่เคยตั้งค่า แอปจะพาไปหน้า ตั้งค่า Jira เอง

  • หยุดแอปด้วย Ctrl + C ใน Terminal ที่รันอยู่
  • อัปเดตด้วย brew upgrade worklog-studio การตั้งค่าและประวัติไม่หาย
  • ถ้าเปิดไม่ได้เพราะพอร์ต 8765 ถูกใช้ แสดงว่ามีตัวเดิมรันค้างอยู่ ให้หยุดตัวเดิมก่อน

ปิด Terminal ไปแล้ว แอปยังรันอยู่ จะหยุดอย่างไร

ถ้ากดปิดหน้าต่าง Terminal เดิม แอปอาจยังรันอยู่เบื้องหลัง เปิด Terminal ใหม่แล้วทำตามนี้:

  1. หาโปรเซสที่ถือพอร์ต 8765: 
    lsof -nP -iTCP:8765 -sTCP:LISTEN
    ในผลลัพธ์ ตัวเลขใต้คอลัมน์ PID คือรหัสโปรเซส ถ้าไม่มีผลลัพธ์ แปลว่าแอปไม่ได้รันอยู่แล้ว
  2. หยุดโปรเซสนั้น (แทน 12345 ด้วย PID ที่ได้): 
    kill 12345
  3. ตรวจซ้ำด้วยคำสั่งในข้อ 1 ถ้าไม่มีผลลัพธ์แล้ว แปลว่าหยุดสำเร็จ

ถ้าโปรเซสยังไม่หยุด ใช้ kill -9 12345 แทน

คำสั่งลัดที่หยุดทันทีโดยไม่ต้องดู PID:

kill $(lsof -tiTCP:8765 -sTCP:LISTEN)
ตรวจก่อนสั่งหยุด

คำสั่งนี้หยุดโปรเซสใดก็ตามที่ถือพอร์ต 8765 อยู่ ถ้าไม่แน่ใจว่าเป็นของ Worklog Studio ให้รันคำสั่งในข้อ 1 ดูก่อน

  2. หา Board ID

    เปิดบอร์ดใน Jira แล้วดู URL ที่ลงท้ายด้วย /boards/9146 ตัวเลขท้ายคือ Board ID ใส่เฉพาะตัวเลข ไม่ใช่ URL ทั้งเส้น ใส่ได้สูงสุด 10 บอร์ด คั่นด้วยจุลภาค

  4. ทดสอบการเชื่อมต่อ

    กด ทดสอบค่าที่บันทึก ถ้าสำเร็จ ป้ายสถานะเปลี่ยนเป็น พร้อมเชื่อมต่อ ถ้าไม่ผ่าน ดูหัวข้อ แก้ปัญหา

    3. ลองพิมพ์ชื่อประชุมในช่อง "ลองชื่อประชุมก่อนบันทึก" แล้วกด ทดสอบการจับคู่ ใช้ร่างที่ยังไม่บันทึกได้
    4. กด บันทึกการจับคู่ ระบบตรวจสิทธิ์อ่านการ์ดทุกใบใน Jira ก่อนบันทึก

เรื่อง token

แอปเก็บ API token เป็นข้อความปกติในไฟล์ใต้ ~/Library/Application Support/Worklog Studio/ ซึ่งจำกัดสิทธิ์ให้เจ้าของเครื่องเท่านั้น อย่าอัปโหลดโฟลเดอร์นี้ขึ้น GitHub หรือแชร์ไฟล์สำรองให้ผู้อื่น

ตั้งค่าผ่านตัวแปรสภาพแวดล้อมแทนได้ไหม

ได้ ใช้ JIRA_BASE_URL, JIRA_EMAIL, JIRA_API_TOKEN และ WORKLOG_TIMEZONE เป็นค่าสำรอง แต่ค่าที่บันทึกในหน้าตั้งค่าจะมาก่อน

เลือกวิธีลงเวลา

ตั้งค่าเสร็จแล้ว งานประจำวันมี 3 ทาง ทุกทางต้องผ่านการตรวจของคุณก่อนส่งเข้า Jira

อยากทำอะไรใช้แท็บเหมาะกับ
เลือกการ์ดแล้วลงเวลาเองลงเวลางานที่ทำจริงแต่ไม่อยู่ในปฏิทิน

ดูว่าสัปดาห์นี้ลงครบหรือยังสรุปรายสัปดาห์เช็กย้อนหลังและหาวันที่ขาด
ตรวจว่ารายการไหนส่งแล้วประวัติ Syncตามรายการที่ผลไม่แน่ชัด
แท็บ ลงเวลา

ลงเวลาจากบอร์ด

  1. โหลดงาน ตรวจ Board IDs แล้วกด โหลดงานจากบอร์ด การ์ดที่อยู่หลายบอร์ดแสดงครั้งเดียว ถ้าบอร์ดใดไม่พบหรือไม่มีสิทธิ์ แอปข้ามบอร์ดนั้นและแจ้ง ID ให้ทราบ
  2. กรองและเลือก ใช้ช่องค้นหา (Issue, ชื่องาน, บอร์ด, สถานะ) กับตัวกรอง สถานะ, ประเภท, การส่งในวันที่เลือก แล้วติ๊กการ์ด ช่องติ๊กหัวตารางเลือกเฉพาะแถวที่แสดงอยู่
  3. ตั้งค่าตั้งต้น ใส่วันที่เริ่มต้นและชั่วโมงเริ่มต้น แล้วกด เพิ่มงานที่เลือก การ์ดเข้าคิวรายการรอบันทึก
  4. ปรับให้ตรงความจริง แก้วันที่ ชั่วโมง และรายละเอียดในแต่ละแถว ลบแถวด้วยปุ่ม ลบ ถ้าทำการ์ดเดียวกันคนละวัน ให้เพิ่มการ์ดนั้นซ้ำอีกครั้ง
  5. ตรวจสอบ กด ตรวจสอบรายการ ระบบรวมชั่วโมงแยกตามวัน ปุ่มบันทึกจะเปิดก็ต่อเมื่อผ่านการตรวจ
  6. บันทึก กด บันทึกลง Jira แล้วยืนยัน แอปส่งทีละรายการและหยุดทันทีเมื่อมีรายการล้มเหลวหรือไม่แน่ชัด จากนั้นตรวจประวัติ worklog ใน Jira อีกครั้ง
ลงเวลาได้เฉพาะ Task และ Sub-task

งานประเภทอื่น เช่น Story, Bug, Epic แสดงเป็นแถวจาง ติ๊กไม่ได้ และเขียนว่า "ลงเวลาไม่ได้" เซิร์ฟเวอร์ปฏิเสธซ้ำอีกชั้นตอนส่ง

รายละเอียดที่ควรรู้

  • ตัวกรอง การส่งในวันที่เลือก เริ่มต้นที่ ยังไม่ส่ง โดยดูจากประวัติในแอปตามวันที่เริ่มต้น ไม่ได้ยืนยันว่า Jira ไม่มี worklog ของการ์ดนั้น
  • รายการจากหน้านี้บันทึกด้วยเวลาเริ่ม 09:00 ของวันที่เลือกตาม Timezone เป็นเวลาอ้างอิง ไม่ใช่เวลาทำงานจริง
  • ส่งได้ไม่เกิน 100 รายการต่อรอบ โหลดได้ไม่เกิน 10 บอร์ด และ 4,000 งานต่อบอร์ด ห้ามลงเวลาวันในอนาคต
  • รายการที่ยังไม่ส่งอยู่ในแท็บเบราว์เซอร์ รีเฟรชแล้วกลับมา แต่ปิดแท็บแล้วหาย
แท็บ Mac Calendar

ลงเวลาจาก Mac Calendar

อ่านประชุมจาก Calendar.app แล้วเสนอการ์ดและเวลาให้ตรวจก่อนลง Jira ไม่มีการลงเวลาอัตโนมัติ

ครั้งแรก: ให้สิทธิ์อ่านปฏิทิน

  1. ตรวจว่าปฏิทินบริษัท (Microsoft 365 / Exchange) แสดงอยู่ในแอป Calendar ของ Mac แล้ว แอปนี้ไม่ขอรหัสผ่านหรือ token ของ Microsoft
  2. เปิดแท็บ Mac Calendar กด อนุญาตให้อ่าน Calendar แล้วเลือก Full Calendar Access ในหน้าต่างของ macOS
  3. ครั้งแรกแอปคอมไพล์ตัวอ่านปฏิทินเอง อาจรอสักครู่
ทำไมต้อง Full Access

macOS ไม่มีสิทธิ์อ่านอย่างเดียวสำหรับ Calendar แอปนี้อ่านอย่างเดียวเท่านั้น ไม่แก้ไขหรือลบเหตุการณ์ใดในปฏิทิน ถ้าเคยกดปฏิเสธ ให้เปิดใหม่ที่ System Settings → Privacy & Security → Calendars

ดึงและตรวจประชุม

  1. เลือกปฏิทิน ติ๊กเฉพาะปฏิทินงานของบริษัท ค่าเริ่มต้นคือไม่เลือกอะไร อย่าใช้ "เลือกทุกปฏิทิน" ถ้ามีปฏิทินส่วนตัว
  2. เลือกสัปดาห์ ใส่วันที่ในสัปดาห์ หรือกดลูกศร
  3. กด ดึงประชุมจาก Mac ระบบเสนอรายการพร้อมการ์ดตามกฎ
  4. ตรวจในตาราง ติ๊กเฉพาะประชุมที่เข้าร่วมจริง แก้การ์ด วันที่ นาที และรายละเอียดได้
  5. กด ตรวจสอบรายการ แล้ว บันทึกลง Jira พร้อมยืนยัน

Today Sync

ปุ่มลัดสำหรับปิดวัน ส่งประชุมของวันนี้ทั้งหมดหลังตรวจรายการในหน้าต่างเดียว

  1. ติ๊กปฏิทินบริษัทก่อน ถ้ายังไม่เลือก จะมีข้อความเตือน
  2. กด Today Sync แอปรีเฟรชประวัติ โหลดปฏิทินวันนี้ และตรวจเวลาที่มีใน Jira
  3. หน้าต่าง ตรวจรายการ Today Sync เปิดขึ้น แสดงสรุป (วันที่ จำนวน ชั่วโมงรวม เวลาเดิมใน Jira จำนวนที่ข้าม) และตารางประชุมทุกรายการ: ลำดับ ชื่อประชุม การ์ด นาที คำเตือน
  4. กด ตกลง บันทึกลง Jira เพื่อส่งทุกรายการ หรือ ยกเลิก เพื่อไม่ส่งอะไร รายการยังติ๊กค้างในตารางให้แก้เอง
รวมเข้ารอบส่งข้าม
ประชุมมีเวลาของวันนี้ที่จับคู่การ์ดได้และยังไม่ส่ง รวมประชุมที่ยังไม่จบและรายการที่มีคำเตือน เช่น เวลาซ้อน (สูงสุด 100 รายการ) รายการที่ส่งแล้วหรือต้องตรวจสอบ, รายการทั้งวัน, รายการที่ยังไม่จับคู่การ์ด
ก่อนกดตกลง

ประชุมที่ยังไม่จบจะถูกส่งด้วยระยะเวลาตามตารางนัด ถ้าเลิกเร็วหรือช้ากว่านั้น ให้ยกเลิกแล้วแก้นาทีในตารางก่อน ถ้าอ่านประวัติหรือเวลาใน Jira ไม่ได้ Today Sync จะไม่ส่ง

แท็บ สรุปรายสัปดาห์

สรุปรายสัปดาห์

อ่าน worklog จริงของคุณจาก Jira มาเทียบเป้าวันละ 8 ชั่วโมง หน้านี้อ่านอย่างเดียว ไม่สร้างหรือเติม worklog ให้

  1. เลือกวันที่ในสัปดาห์ หรือกดลูกศรเลื่อนทีละสัปดาห์
  2. ดูสรุป 3 ค่า: บันทึกแล้ว (จ.–ศ.), เป้าหมายสัปดาห์นี้, วันทำงานที่ครบ 8 ชั่วโมง
  3. กด โหลด worklog จาก Jira เมื่ออยากอัปเดตข้อมูลล่าสุด
สถานะวันความหมาย
ครบ 8 ชั่วโมงบันทึกถึงเป้าแล้ว
ยังขาดเวลาวันที่ผ่านมาแล้วแต่ยังไม่ครบ
วันนี้ · ยังไม่ครบวันนี้ยังลงไม่ถึงเป้า
ยังไม่ถึงวันวันในอนาคต ไม่นับว่าค้าง
วันหยุด BOTเป้าเป็น 0 ชั่วโมง แสดงชื่อวันหยุด
  • worklog วันเสาร์–อาทิตย์แสดงแยก และไม่นับกับเป้าวันทำงาน นับเฉพาะ worklog ที่ผู้เขียนคือบัญชี Jira ของคุณ
  • ผลถูกเก็บ 5 นาที สลับแท็บกลับมาไม่ต้องโหลดใหม่ ปุ่มโหลดใหม่อ่าน Jira ใหม่เสมอ และแคชถูกล้างทันทีหลังคุณบันทึกเวลาใหม่

สัปดาห์ที่ลงเวลาไม่ครบ

อยู่ในแท็บเดียวกัน เลือก ปี ค.ศ. และ ช่วงตรวจ (4 สัปดาห์ล่าสุด, 12 สัปดาห์ล่าสุด หรือทั้งปี) แล้วกด ตรวจ worklog ระบบจัดกลุ่มวันทำงานที่ไม่มี worklog หรือน้อยกว่า 8 ชั่วโมงเป็นรายสัปดาห์ กดการ์ดสัปดาห์เพื่อดู worklog ของสัปดาห์นั้นด้านบน

  • ตรวจถึง "เมื่อวาน" ไม่รวมวันนี้ วันเสาร์–อาทิตย์ และวันหยุด BOT
  • การตรวจทั้งปีอาจใช้เวลาหลายนาที เพราะอ่าน Jira ครั้งเดียวทั้งช่วง

วันหยุด BOT

  • ดึงจากหน้าวันหยุดสถาบันการเงินของธนาคารแห่งประเทศไทย เก็บแคชรายปี รีเฟรชเองทุก 24 ชั่วโมง หรือกด ซิงก์วันหยุด BOT ใหม่
  • ถ้าดึงไม่ได้ ใช้แคชเก่าพร้อมแจ้งเตือน ถ้าไม่มีแคชเลย รายการแจ้งเตือนจะไม่ทำงานเพื่อกันสรุปผิด และเป้าในหน้าสรุปรายสัปดาห์เป็นค่าชั่วคราว
ใช้เป็นแนวทาง

ปฏิทิน BOT อาจไม่ตรงกับวันหยุดของบริษัท และระบบไม่รู้วันลาส่วนตัวของคุณ

แท็บ ประวัติ Sync

ประวัติ Sync และการกันบันทึกซ้ำ

แสดงสถานะล่าสุดของ worklog ที่แอปส่งหรือพบใน Jira ทั้งจากบอร์ดและ Calendar

  • ค้นหาด้วยรหัส Issue และกรองสถานะ: บันทึกแล้ว / ต้องตรวจสอบ / ไม่พบรายการตรงกัน
  • แต่ละแถวแสดง Issue วันที่ เวลา แหล่งที่มา (ลงเวลา / Mac Calendar / พบใน Jira) สถานะ รหัส worklog และเวลาที่บันทึก กด โหลดประวัติใหม่ เพื่ออ่านไฟล์อีกครั้ง
  • งานที่ไม่อยู่ในประวัติ ไม่ได้แปลว่า ไม่มี worklog ใน Jira

กันบันทึกซ้ำ

ก่อนส่งทุกรายการ แอปอ่าน worklog ของการ์ดนั้นในวันนั้น แล้วข้ามถ้ามี Issue วันที่ ระยะเวลา และรายละเอียดตรงกัน รวมถึงของที่สร้างด้วยมือหรือจากเครื่องอื่น งานช่วงเดียวกันที่รายละเอียดต่างกันถือเป็นคนละงานและส่งได้ ถ้าเช็กไม่ได้ ระบบหยุดและไม่เขียนแถวนั้น

เมื่อผลการส่งไม่แน่ชัด

ถ้าเครือข่ายหลุดหลังส่ง ระบบทำเครื่องหมาย ต้องตรวจสอบ และห้ามส่งซ้ำ ทำตามนี้:

  1. เปิดแท็บ ประวัติ Sync
  2. กด ตรวจรายการไม่แน่ชัดใน Jira
  3. ถ้าพบ worklog ที่ตรงกัน สถานะเป็น บันทึกแล้ว ถ้าไม่พบ เป็น ไม่พบรายการตรงกัน และส่งใหม่ได้หลังตรวจเอง
ข้อจำกัดของการเทียบ

เทียบระยะเวลากับรายละเอียดที่ตรงกันทุกตัวอักษร ถ้าถูกแก้ภายหลังหรือมีสิทธิ์จำกัด อาจจับคู่ไม่เจอ ให้เปิด Jira ดูเองก่อนส่งซ้ำ

อ้างอิง

ข้อมูลและความปลอดภัย

ข้อมูลเก็บที่ไหน
การตั้งค่า Jira, ประวัติ Sync, แคชวันหยุด BOT, ตัวอ่านปฏิทิน~/Library/Application Support/Worklog Studio/ โฟลเดอร์สิทธิ์ 0700 ไฟล์ 0600 ไม่ถูกลบเมื่ออัปเดตหรือถอนแอป
รายการร่าง รายการประชุม ผลสรุปรายสัปดาห์sessionStorage ของแท็บเบราว์เซอร์ อยู่ได้ 12 ชั่วโมง (ผลรายสัปดาห์ 5 นาที) ไม่เก็บ token ปิดแท็บแล้วหาย ไม่แชร์ข้ามแท็บหรือเครื่อง

หลักที่แอปยึด

  • เปิดเฉพาะ 127.0.0.1 ห้ามเปิดผ่าน reverse proxy หรือเครือข่ายร่วมกัน และไม่มีระบบล็อกอินของแอปเอง
  • ใช้บัญชีและ token ของคุณเอง ไม่ใช่บัญชีกลาง Jira เป็นผู้ตัดสินสิทธิ์สร้าง worklog
  • ส่งทีละรายการ หยุดเมื่อมีรายการล้มเหลวหรือไม่แน่ชัด และไม่ย้อนกลับรายการที่สร้างแล้ว
  • ออกแบบสำหรับเวลาที่ทำจริงที่คุณยืนยันเอง ไม่ใช่การสร้าง timesheet ปลอม

ข้อจำกัด

  • ส่งไม่เกิน 100 รายการต่อครั้ง, 10 บอร์ด, 4,000 งานต่อบอร์ด, 30 กฎจับคู่
  • การกันบันทึกซ้ำเป็นแบบพยายามเต็มที่ เทียบจากรายละเอียดที่ตรงกัน ไม่ใช่การรับประกันระดับระบบ
  • EventKit ไม่มีธงประชุมส่วนตัวที่เชื่อถือได้ ระบบกรองเฉพาะ placeholder ที่ชัดเจน จึงต้องเลือกเฉพาะปฏิทินงาน
อ้างอิง

แก้ปัญหาที่พบบ่อย

เปิดแอปแล้วขึ้นว่าพอร์ต 8765 ถูกใช้งาน

มีตัวเดิมรันอยู่ ให้หยุดด้วย Ctrl + C ในหน้าต่าง Terminal เดิม ถ้าปิดหน้าต่างนั้นไปแล้ว ดูวิธีใน ติดตั้งและเปิดแอป หัวข้อ "ปิด Terminal ไปแล้ว"

ทดสอบการเชื่อมต่อไม่ผ่าน

ตรวจว่า URL ขึ้นต้นด้วย https:// และเป็นโดเมน .atlassian.net อีเมลตรงกับบัญชีที่สร้าง token, token ยังไม่หมดอายุ และบัญชีมีสิทธิ์ Browse projects / Work on issues ถ้าใส่ Board ID เป็น URL ทั้งเส้น ให้ใส่เฉพาะตัวเลข

โหลดบอร์ดแล้วบางบอร์ดถูกข้าม

แอปแจ้ง ID ของบอร์ดที่ไม่พบหรือไม่มีสิทธิ์ ตรวจ ID จาก URL ของบอร์ด หรือขอสิทธิ์เข้าถึงบอร์ดนั้น บอร์ดอื่นยังใช้ได้ตามปกติ

ติ๊กการ์ดไม่ได้

การ์ดนั้นเป็นประเภทที่ไม่ใช่ Task หรือ Sub-task (เช่น Story, Bug, Epic) ให้เลือก Task หรือ Sub-task ของงานนั้นแทน

อ่านปฏิทินไม่ได้

ตรวจที่ System Settings → Privacy & Security → Calendars ให้ Full Access กับ Worklog Studio Calendar Reader แล้วเปิดหน้านี้ใหม่ ถ้าไม่พบคอมไพเลอร์ ให้ติดตั้ง xcode-select --install

ขึ้น "Unable to block on applications" ตอนอ่านปฏิทิน

เป็นข้อผิดพลาดชั่วคราวตอนเรียกตัวอ่านปฏิทินซ้อนกัน เวอร์ชัน 0.1.1 ลองใหม่ให้เองสูงสุด 3 ครั้ง ถ้ายังพบ ให้รีเฟรชหน้าอีกครั้ง

Today Sync ไม่เปิดหน้าต่างตรวจรายการ

อ่านข้อความใต้ปุ่มดึงประชุม สาเหตุทั่วไปคือยังไม่ได้เลือกปฏิทิน อ่านประวัติหรือเวลาเดิมใน Jira ไม่ได้ หรือวันนี้ไม่มีประชุมที่พร้อมส่ง (ส่งแล้ว ทั้งวัน หรือยังไม่จับคู่การ์ด)

รายการติด "ต้องตรวจสอบ" ส่งซ้ำไม่ได้

ไปที่ประวัติ Sync กด ตรวจรายการไม่แน่ชัดใน Jira เพื่อให้ระบบหาว่ามี worklog อยู่แล้วหรือไม่ ถ้าไม่แน่ใจ ให้เปิด Jira ดูประวัติ worklog ของการ์ดนั้นเอง

รีเฟรชแล้วข้อมูลที่โหลดไว้หาย

ข้อมูลเก็บไว้ในแท็บเดิมเท่านั้น ถ้าปิดแท็บ ใช้เบราว์เซอร์อื่น หรือผ่านไปเกิน 12 ชั่วโมง ต้องโหลดใหม่ เมื่อเปิดหน้า ช่อง Status บอกผลการกู้คืน

ถอนการติดตั้ง

รัน brew uninstall worklog-studio ข้อมูลใน ~/Library/Application Support/Worklog Studio/ ยังอยู่ ลบเองถ้าไม่ต้องการ และควรเพิกถอน API token ที่หน้า Atlassian ด้วย
